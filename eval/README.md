# 정확도 평가 (Phase 10)

> **합성 데이터 기준** 숫자입니다. 실제 문서(다양한 양식·손글씨·저화질)의 정확도와 다를 수 있습니다.

## 데이터 — `data/`

`make_dataset.py`로 만든 공고·계약서 **40쌍(이미지 80장)**. 일자리 8종에 변형을 준다.

| 변형 | 쌍 수 | 예 |
|---|---|---|
| 동일 (오탐 확인) | 7 | 범위 임금의 하한으로 계약, 공고에도 포괄임금·수습이 있었음 |
| 임금 감액 | 7 | 월급·시급·연봉 감액, 최저임금 미달 |
| 수습 신설 | 5 | 3개월 90%, 3개월 100%, 6개월 80% |
| 포괄임금 전환 | 6 | 연장 10~30시간 포함 (일부는 기본 시급이 최저임금 미달) |
| 필수 명시사항 누락 | 6 | 임금 지급일·휴일·연차·소정근로시간 |
| 고용형태 변경 | 3 | 정규직 → 계약직·프리랜서 |
| 근무일·시간 증가 | 4 | 주 5일 → 6일, 출근 1시간 앞당김 |
| 위약·손해배상 조항 | 3 | 교육비 공제, 조기 퇴사 배상 |
| 근무지 변경·임금 비공개 | 2 | |
| **사진 효과** (기울기·그림자·흐림) | 이미지 12장 | 다른 변형과 겹쳐 적용 |

- 핵심 경고(불리 변경·법 기준 확인) **50건**, 누락·모호 **10건**.
- `answer_key.json`의 경고는 변형을 보고 사람이 정했고, 정답 JSON을 엔진에 넣으면 그대로 나오는지 `backend/tests/test_eval_dataset.py`가 확인한다.

```powershell
backend\.venv\Scripts\python -m pip install -r eval\requirements.txt   # Pillow (생성기 전용)
backend\.venv\Scripts\python eval\make_dataset.py
```

## 실행 — `run_eval.py`

```powershell
backend\.venv\Scripts\python eval\run_eval.py --provider mock                                   # 파이프라인 점검 (100%가 정상)
backend\.venv\Scripts\python eval\run_eval.py --provider gemini --model gemini-3.5-flash-lite
backend\.venv\Scripts\python eval\run_eval.py --provider gemini --model gemini-3.5-flash-lite --prompt extract_v2
```

- 서비스와 같은 순서로 처리: 추출 → 인용 검증 → 마스킹 → 판정.
- 추출 결과는 `cache/`에 저장해 재실행 시 다시 부르지 않는다 (git 제외). 결과는 `results/날짜_프롬프트_모델.json`.
- **무료 티어 한도 주의**: `gemini-3.5-flash`는 하루 20회라 한 번(80회)에 끝나지 않는다. 429가 나면 바로 멈추고, 다음 날 다시 실행하면 캐시 이후부터 이어간다.

## 지표

| 지표 | 뜻 |
|---|---|
| 추출 정확도 | 판정에 쓰는 16개 항목 × 80장 중 정답과 같은 값 (근무지·지급일은 포함 관계, 휴일·연차·위약 조항은 있음/없음만) |
| 인용 폐기 | 근거 인용이 원문에 없어 값을 버린 수 |
| OCR 원문 일치율 | 이미지에 그린 글자(`data/*.txt`)와 모델이 옮긴 원문의 유사도 (공백 무시) |
| **핵심 재현율** | 불리 변경·법 기준 확인 50건 중 잡은 수 — **가장 중요** (놓치면 사용자가 모르고 서명) |
| 정답에 없는 경고 | 오탐. 사용자가 불필요하게 불안해지거나 질문하게 됨 |

## 결과

### 기준선: `extract_v1` (2026-10-08)

| 모델 | 범위 | 추출 정확도 | 인용 폐기 | OCR 일치율 | 핵심 재현율 | 오탐 (핵심 / 누락·모호) | 완전 일치 쌍 |
|---|---|---|---|---|---|---|---|
| gemini-3.5-flash-lite | 40쌍 | 1259/1280 (98.4%) | 9 | 0.997 | **50/50** | 0 / 10 | 32/40 |
| gemini-3.5-flash | 11쌍 (일일 한도) | 352/352 (100%) | 0 | — | 10/10 | 0 / 0 | 11/11 |

틀린 21건은 전부 두 항목에 몰려 있다 (사진 이미지에서는 오류 없음):

1. **고용형태 8건** — 아르바이트 공고·계약서에서 `"아르바이트"`를 그대로 값으로 냄 (스키마 선택지에 없음, 정답 `"기타"`).
   공고는 `기타`, 계약서는 `아르바이트`처럼 한쪽만 바뀌면 엔진이 "고용형태 표현이 다름 — 확인 필요"(모호) 경고를 낸다 → 오탐 7건.
2. **근무지 13건** — 프롬프트 규칙 6("주소의 번지 이하는 ***로 가린다")을 따르느라 원문의 `○○`를 `***`로 바꿔 적음.
   원문과 인용의 가림이 서로 어긋나면 인용 검증에서 값이 버려지고(9건), 값에 `***`가 남으면 계약서와 근무지가 달라 보인다 → 오탐 3건.

두 문제 모두 판정의 핵심 경고에는 영향이 없었지만(재현율 50/50), 사용자 화면에 불필요한 "확인 필요"가 뜬다.

### `extract_v2` (2026-10-08) — 현재 기본값

v1에서 두 규칙만 바꿨다 (나머지는 그대로라 차이를 이 수정 탓으로 볼 수 있다).

- 규칙 6: 사업장·근무지 주소는 가리지 않고 그대로(○○ 포함). 개인정보를 가릴 때는 원문과 인용을 똑같이 가린다.
- 규칙 7: 고용형태 값은 8개 선택지만. 아르바이트·파트타임 → `"기타"`.

같은 모델·같은 40쌍으로 비교:

| 지표 (gemini-3.5-flash-lite) | v1 | v2 |
|---|---|---|
| 추출 정확도 | 1259/1280 (98.4%) | **1280/1280 (100%)** |
| └ 사진 이미지 | 192/192 | 192/192 |
| 인용 폐기 | 9 | **0** |
| OCR 원문 일치율 | 0.997 | 0.999 |
| 핵심 재현율 | 50/50 | 50/50 |
| 오탐 (누락·모호) | 10 | **0** |
| 경고 목록 완전 일치 | 32/40 | **40/40** |
| 문서당 시간 | 4.8초 | 4.7초 |

v2 첫 실행에서는 오탐이 4건 남았다. 원인은 계약서 제목 "기간제 근로자 표준근로계약서"를 보고 모델이 `기간제`를 고르는데 공고는 `계약직`이라 엔진이 "표현이 다름"으로 본 것.
고용노동부 표준 양식 이름이라 실제 문서에서도 흔할 것이므로 프롬프트가 아니라 **엔진**에서 기간제 = 계약직으로 보게 고쳤고(`engine.SAME_EMPLOYMENT`), 채점도 같은 기준을 쓴다. 위 표는 이 수정을 반영해 캐시로 다시 채점한 값이다.
